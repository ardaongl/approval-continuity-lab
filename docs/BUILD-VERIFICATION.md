## Evidence and reproduction

Use CPython 3.12.14 and SQLite ≥3.35.0 on macOS/Linux POSIX. The executed local
reference environment is CPython 3.12.14 (Clang22.1.3), SQLite3.53.1,
macOS26.5.2 arm64. Exact executable/full versions and candidate hashes live in
the ignored evidence, rather than hardcoded workstation paths in product code.

The final full-suite command is:

```sh
ACL_TEST_EVIDENCE=.local-verification/build/final-snapshots \
  .venv/bin/python -B scripts/verify.py final-suite -- \
  .venv/bin/python -B -m unittest discover -s tests -t . -v
```

Each verification wrapper saves its actual argv, exit, timestamp, source-file
hashes/fingerprint, environment and complete stdout/stderr. Final outputs are
indexed at `.local-verification/build/final/result.json` and
`.local-verification/build/final-attestation.json`. The test count and individual
names are in `final/stderr.txt`; no count is inferred from generated test files.
`final-snapshots/cases/` contains expected codes, observed reports and independent
fresh-connection raw SQL snapshots per test. Dedicated race/crash/SIGINT records
retain barrier transcripts, child exits and held/reopened/final SQL state.
Distribution records contain exact build/install/installed-command logs,
archive inventories/hashes and calibrated offline-guard observations.

packaging≥24.0; build-only packaging26.3 is pinned to the observed bundled version.

Imports are checked against the installed environment, never the source path.

includes tests and their necessary data.

## Limitations and next gate

The single SQLite transaction protects only the simulated service, consumption
and durable result. The host/operator/database/clock are trusted. Personas do not
authenticate production users; hashes do not attest executable code. Tests prove
the specified process-crash schedules, not arbitrary power loss, external exactly
once execution, global time or resistance to direct database edits.

SQLite write-fault tests use a real calibrated authorizer denial inside an actual
transaction. Uncertain COMMIT tests simulate lost outcome knowledge after an actual
commit and independently inspect/reconcile the result; they do not pretend to
reproduce physical disk failure. Runtime IO audit instrumentation explicitly
excludes interpreter import/cache/native behavior it cannot intercept.

Local evidence covers macOS arm64. The prepared Ubuntu/macOS hosted workflow has
not run; Linux support still needs hosted evidence. Action pins were read from
the official [checkout releases](https://github.com/actions/checkout/releases) and
[setup-python releases](https://github.com/actions/setup-python/releases), then
resolved through GitHub's read-only tag API; exact responses are retained in
`.local-verification/build/action-pins.json`. No push was performed.

Independent targeted M0 evidence was retained before state transition. The prior
comprehensive M0 transcript is unavailable and was never fabricated. Independent
adversarial product audit and any remote publication remain separate authorized
phases. Stop at this local gate.
