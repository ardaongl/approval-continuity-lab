# Binding and canonicalization (normative)

## Scalar and JSON grammar

Input is UTF-8 without BOM, maximum 65,536 bytes including whitespace. One JSON value, no trailing non-whitespace. Decode with duplicate-key detection at every object depth, before constructing mappings. Reject malformed UTF-8, lone surrogates, NaN/Infinity, fractional/exponent numbers (even 1.0/1e0), and nesting greater than 16 (root container depth 1). Integer lexical -0 normalizes to 0. All integer fields reject JSON booleans and must be in 0..9,007,199,254,740,991; revision fields are 1..that maximum. Any increment/addition overflow returns LIMIT_EXCEEDED without mutation. Identifiers are ASCII [a-z][a-z0-9_-]{0,63}; enum/tool values explicitly override that grammar. Artifact digest is exactly "sha256:" followed by 64 lowercase hex digits; no aliases, URLs or uppercase. Hex digests without artifact prefix are 64 lowercase hex.

No Unicode normalization, case folding, whitespace trimming or semantic coercion. Unicode scalar sequences compare exactly: composed and decomposed strings differ. Only description, service display_name and decision.reason accept arbitrary valid Unicode scalar characters, subject to their field-specific UTF-8 byte limits and exclusions; identifiers remain ASCII and all other restricted grammars remain unchanged. Description ≤4096 UTF-8 bytes; service display_name ≤128 UTF-8 bytes; decision.reason is 1..1024 UTF-8 bytes. Reject U+0000 in all strings and reject surrogate code points after JSON decoding (a valid escaped surrogate pair represents one supplementary-plane scalar and is permitted in these Unicode fields). Other controls in description/display_name/decision.reason are allowed but always escaped when rendered under C. Text is never executed.

Canonical JSON C(x): keys sorted by Unicode code point, arrays preserve order, separators comma and colon without spaces, ensure_ascii=true escaping with lowercase hex, JSON boolean/null lowercase, integers minimal decimal (zero is 0), slash not escaped, quote/backslash and standard short control escapes as CPython json.dumps(...,sort_keys=True,separators=(',',':'),ensure_ascii=True,allow_nan=False). Encode ASCII/UTF-8, no BOM or terminal newline. Object member order and insignificant input whitespace do not affect C. Missing is distinct from null: every listed field required; only explicitly nullable fields accept null. Unknown keys fail before digest/comparison. Duplicate keys fail even if values are equal. Before JSON decoding, a bounded quote/escape-aware container scan rejects depth17 without recursive parsing. Reject bad numeric tokens via strict decoder hooks; then bounded shape validation. Duplicate/syntax/encoding failures use the generic decode-error detail. Limits cannot be checked only after unbounded recursive decoding.

Digest H(domain,x) = lowercase hex SHA-256 of ASCII "ACL/v1/" + domain + one NUL byte + C(x). Domains: plan, proposal, review, decision, execution. Not keyed; not authentication. All comparisons use validated canonical values, with digests as integrity/lookup aids; do not compare unvalidated client hashes instead of actual contents.

## Agent submission and stored proposal

propose command body has exactly:
schema_version=1; proposal_id; request_id; context_id; reviewer_id; plan; selected_step_id; pending_deadline_ms; grant_ttl_ms; description; replaces_proposal_id (identifier or null).

plan is exactly {revision,steps}; steps has exactly one element {step_id,tool_id,arguments}; tool_id must be deploy_artifact; arguments is exactly {service_id,artifact_digest}. selected_step_id must equal that sole step_id. Plan revision is a positive integer. A proposed extra step, reordering constructed with extra steps or changing operation is invalid, never inferred equivalent. New revision with unchanged step is a different bound plan. There are no read-only or hidden executable steps.

context_id must equal Caller's selected context. requester_id, agent_id, run_id, tenant, environment, executor_id and context_revision are copied from that context, not supplied as overrides. Tool revision comes from registry. Policy revision comes from tenant policy; reviewer_eligibility_revision comes from designated reviewer/tenant row. Expected target revision and current artifact come from service row; service tenant/environment must match context. created_at_ms is sampled by mediator. Deadline must be > created_at_ms and no more than 86,400,000 ms later. grant_ttl_ms is 1..86,400,000, validated with overflow checks at approval too. Reviewer must be an eligible reviewer persona at creation and decision, different from requester (roles make this explicit). Tenant policy must be enabled.

Stored immutable proposal P contains exactly:
schema_version, proposal_id, request_id, context_id, requester_id, agent_id, run_id, tenant, environment, executor_id, context_revision, reviewer_id, reviewer_eligibility_revision, policy_revision, tool_id, tool_revision, plan, plan_digest, selected_step_id, target_service_id, expected_target_revision, prior_artifact_digest, created_at_ms, pending_deadline_ms, grant_ttl_ms, replaces_proposal_id.

Tool/target/arguments are deliberately redundant for readable review: require exact consistency with the sole plan step. plan_digest=H(plan,plan). description is stored separately as immutable untrusted annotation; it is excluded from P, all authority and all digests. No later edit API; changed cosmetic notes require a new request but do not change canonical executable bytes in isolated canonicalization tests. IDs, revisions, deadlines and grant period are bound too.

proposal_digest=H(proposal,P). Review R is exactly {kind:"approval-review-v1",proposal:P}; review_digest=H(review,R). Store C(P), C(R) and those digests at creation. R includes all of P, including previous artifact and every redundant binding. No self-referential review_digest inside P/R. Render only stored R; description is a separately labeled "UNTRUSTED DESCRIPTION" JSON-escaped string. No truncation or terminal control interpretation. Text review prints all fields using JSON-pointer paths in sorted object/array traversal, with each leaf's C(value); arrays also get a length line. Empty containers are represented explicitly. --format json returns R verbatim in data.review, not an agent summary.

The designated reviewer confirms the stored review_digest in decide. An edited client review/plan is not accepted. A different executable field, scope reduction, target, context, deadline or plan revision requires a new proposal/request identity and review. A replacement may name an old proposal in the same context; it must be owned in the selected context and pending/approved or already superseded, and not consumed/rejected/revoked/expired. Atomically mark a live old proposal superseded and link the new ID. No replacement inference or grant transfer.

## Immutable decision and approval identity

decide body: {schema_version:1,approval_id,proposal_id,review_digest,decision,reason}.
decision is approve or reject; reason is an ASCII/Unicode scalar string, including non-ASCII characters, 1..1024 UTF-8 bytes, no NUL or decoded surrogate code points. The scalar grammar, Unicode non-normalization and canonical serialization C above are normative for reason too. Reason is explanatory content and does not independently grant execution authority; it remains part of immutable D and its digest, and a changed reason under an existing approval identity remains conflicting reuse. Approval identity is supplied explicitly and globally unique, distinct from proposal/request/execution identities by field namespace (same string allowed across namespaces). Caller must be designated reviewer; actor identity is derived from Caller, never body.

Decision D is immutable:
{schema_version:1,approval_id,proposal_id,proposal_digest,review_digest,reviewer_id,decision,reason,decided_at_ms,expires_at_ms}.
For approve, expires_at_ms=decided_at_ms+P.grant_ttl_ms; for reject it is null. D digest is H(decision,D). The reviewed proposal is not retroactively modified to add approval time. The full approval envelope is {proposal:P,review:R,decision:D,decision_digest}; these layers bind the reviewer, decision time and fixed expiry without a circular hash. Lifecycle status is mutable, separate from all layers.

An exact repeated decision body for the same approval_id, proposal and reviewer returns the stored decision (no new time or expiry), even if lifecycle changed later. Different reuse returns IDEMPOTENCY_CONFLICT. A second approval_id for an already decided proposal returns INVALID_STATE.

## Submitted execution intent

execute body:
{schema_version:1,execution_id,approval_id,intent:{proposal_id,proposal_digest,review_digest,binding:P}}.
Incoming binding is checked for exact field shape, scalar types/bounds and one-step cardinality; redundant digest/cross-field consistency is not recomputed as an input error. Its well-typed values are compared to the trusted stored P, so a single changed bound field returns BINDING_MISMATCH. C(intent.binding) must equal stored C(P); proposal/review digests must equal stored values, not merely be self-consistent. Caller context must resolve to P.context_id and requester_id; current-context revision checks are separate. execution digest H(execution,{schema_version:1,execution_id,approval_id,actor_id,context_id,intent}) uses actor/context as originally asserted/resolved identity, without current mutable revisions. Store full canonical request, not only its digest, for idempotency equality.

A changed submitted intent is denied with BINDING_MISMATCH while a still-valid stored approval remains approved. A changed authoritative context/target instead supersedes the live proposal; see precedence in [state/time](state-time.md). Neither denial records an execution nor changes target. Execution IDs are reserved only by successful committed executions, not denied attempts.
