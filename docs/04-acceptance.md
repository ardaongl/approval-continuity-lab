# Acceptance criteria and executable evidence map

All requirements below are **NOT_RUN**. Named test modules and commands are planned implementation deliverables. AC-01..AC-14 preserve discovery D01..D14 one-to-one. Tests use fresh files/connections, not in-memory SQLite for transactional/process acceptance.

Common initial state F: [base config](fixtures/base-config.json) initialized at1000; proposal p1/q1/c1 at1000; reviewer rev_a approves a1 at1500 with expiry2500; service svc1=A/rev1; no executions. "Approved F" includes immutable P/R/D from [fixtures](05-fixtures.md). A/B/C are fixed syntactically valid artifact identifiers, not fetched blobs. Unless overridden, execute x1 at1600 as req_a/c1. Domain denials are complete reports with exit3; observer/process termination tests inspect state independently. A test runner command passes only if every required case passes; no platform skip on supported POSIX.

Each module command is `.venv/bin/python -B -m unittest tests.acceptance.test_dNN -v`, replacing NN with the exact two-digit ID in its heading. Every command must exit0; negative *child command* exits are explicitly asserted. Evidence includes case name, command/exit, expected-versus-observed, raw SQL snapshots, report bytes, environment and candidate fingerprint. AC-15–18 use their listed commands.

## AC-01 / D01 — approved execution

Initial: approved F. Ordering: execute x1 at1600, inspect through fresh connection. Transition approved→consumed. Persistent: svc1=B/rev2; exactly one execution x1/a1 with before1/after2/time1600 and matching result; svc2/svc3 unchanged; decision expiry2500 unchanged; floor1600; one consumed transition. Report exactly [D01 golden](fixtures/d01-report.golden.json), code OK/committed, child exit0. Oracle: test-owned raw SELECTs for all affected/unaffected rows, byte comparison to the authored golden, and independent expected revision arithmetic. Planned module: tests.acceptance.test_d01.

## AC-02 / D02 — submitted scope and plan mutations

Initial: independent approved F per variant. Mutate exactly one valid executable field: artifact, service/target ID, tenant, environment, agent/requester, run, context ID/revision, executor, policy/tool/eligibility revision, plan revision, step ID, deadline, TTL, proposal identity/digest/review digest. Full intent has typed fields; stored P never changes. Owning caller stays req_a/c1 unless testing caller mismatch. Well-typed mismatches → BINDING_MISMATCH, approved stays approved, no execution/effect, report mismatch paths sorted. Wrong actual caller req_b/c2 or req_a/c3 → CALLER_MISMATCH before any lifecycle update. Extra step/reordered two-step construction → INPUT_INVALID before DB (one-step limit), not semantic equivalence. Then a correct request succeeds, proving denial did not consume approval. Independent oracle compares original canonical stored proposal/decision bytes, status, target revisions, row counts and fixed pointer expectations. Planned module: tests.acceptance.test_d02.

## AC-03 / D03 — strict canonicalization

Initial: no DB for pure parsing; seeded state for CLI rejection cases. Submit reordered keys/whitespace and -0 where nonnegative ints permit; expect exact canonical vectors. Equivalent submissions under the same idempotency key retrieve the same P. Duplicate keys at root/nested depth (even equal values), null required fields, missing/extra fields, bool-as-int, floats/exponents/nonfinite numbers, BOM, invalid UTF-8, lone surrogates, integer overflow, depth17 and byte65537 → INPUT_INVALID/INPUT_LIMIT as specified; unsupported version → UNSUPPORTED_VERSION. No DB changes on parse failure. At size/depth/integer exact boundaries valid shape succeeds; maximum revision increments fail without overflow. Composed/decomposed Unicode stays distinct; non-BMP scalar escapes are pinned. Oracle: literal canonical ASCII and digest assets plus independent hashlib/domain-separation calculation, not production helpers; verify unchanged DB. Planned module: tests.acceptance.test_d03.

AC-03 also applies the independent [decision-reason Unicode boundaries](06-test-plan.md#decision-reason-unicode-boundaries): accepted scalar strings retain exact sequences and canonical bytes; invalid NUL/surrogate/length inputs reject before DB access. Existing vectors remain frozen.

## AC-04 / D04 — expiry and time floor

Initial: pending variant p1 at1000 or approved F. Pending approve at1999 succeeds; at2000/2001 persists expired/PENDING_EXPIRED, no decision. Approved execute at2499 succeeds;2500/2501 persists expired/GRANT_EXPIRED, no execution/effect. Each variant fresh. An observed inspect at2400 persists floor2400; next command2399 returns CLOCK_REGRESSION with floor/status unchanged. Restart and repeat2399; still denies. Equal2400 accepted. Expired state never revives when clock falls. Expiry from a late decision1999 equals2999, not proposal deadline2000; grant TTL remains fixed on retry. Overflow at approval returns LIMIT_EXCEEDED with no decision. Hold transaction after final check2499, permit later wall-clock commit: result authorized_at2499; no claim at commit time. Oracle reads meta/status/decision expiry, uses fixed injected Clock and independent arithmetic; no sleep expiry oracle. Planned module: tests.acceptance.test_d04.

## AC-05 / D05 — replay/idempotency

Initial: approved F. Commit x1 at1600; same canonical request/key/owner retrieves identical data.result with replayed=true, no time observation. Repeat after policy/eligibility/context/service mutations and after expiry/backward now; retrieval still returns original, no extra effect. Same execution_id with another artifact/approval/caller payload → IDEMPOTENCY_CONFLICT (unauthorized caller remains CALLER_MISMATCH); another ID with a1 → APPROVAL_CONSUMED. Correct reuse after a denied unreserved x2 can execute on fresh approval. Propose and decision exact retries preserve original bytes/deadlines, conflicting key reuse denies; another decision ID after decided → INVALID_STATE. Oracle counts executions and revision deltas (excluding explicit admin changes), compares immutable result bytes and floor across historical retrievals. Planned module: tests.acceptance.test_d05.

## AC-06 / D06 — two-process execution race

Initial: approved F in disk DB. Run independent worker connections as [schedule](contracts/concurrency-recovery.md): both ready, A holds transaction, B attempts BEGIN, A commits, B proceeds. Different IDs: A OK/consumed then B APPROVAL_CONSUMED; reverse schedule swaps winner. Same-ID variant: first OK, second OK/replayed, one execution. A separate coordinator-controlled hold forces B to return real STORAGE_BUSY before A is released, then B explicitly retries; this proves contention without guessing scheduling. Persistent target B/rev2, exactly one consumed transition/result, no leaked locks. Scenario report orders logical participant observations, not arrival times. Oracle: independent coordinator pipes/child exits and raw fresh-connection state; no mocked lock/sleep sequencing. Planned module: tests.acceptance.test_d06.

## AC-07 / D07 — revocation orderings

## AC-08 / D08 — target drift/ABA/substitution

## AC-09 / D09 — authoritative tool/context/policy/eligibility drift

Initial: independent approved F per variation. Admin bump tool implementation revision (same name), context executor/revision, policy revision (including enabled=false), or reviewer eligibility/revision (including allowed=false). Execute unchanged intent1600. Expect superseded with TOOL_CHANGED, CONTEXT_CHANGED, POLICY_CHANGED or REVIEWER_CHANGED according to precedence; A/rev1, no execution. Multiple simultaneous changes choose context→tool→policy→reviewer→target, with expiry first. Restore values with another revision bump does not revive. Oracle: immutable P versus raw current rows and transition reason; expected codes predetermined, not produced by evaluator under test. Planned module: tests.acceptance.test_d09.

## AC-10 / D10 — crash and restart

Initial: independent approved F for each crash. A: real subprocess stages all three writes and floor1600, blocks before_commit; coordinator reads old committed state, SIGKILL/reap, reopen. Final approved, A/rev1, no execution/consumed transition, floor1500. Identical retry1600 commits once. B: worker commits, pauses before any response, coordinator reads consumed+B/rev2+one result, SIGKILL/reap, reopen; exact retry returns stored data.result with replayed=true and no second effect. Compare original stored result without relying on missing stdout. Verify journals recovered through SQLite, never manually deleted. Process itself exits by signal; scenario coordinator produces verified report. Oracle: separate raw connections, immutable decision bytes, target/revision/result/transition/floor reads and barrier transcript. Planned module: tests.acceptance.test_d10.

## AC-11 / D11 — trusted review

Initial: pending p1 with deliberately misleading description including newline, ESC, bidirectional Unicode and forged "approve a different target" text. review emits all P fields from stored R, digest matches fixed R asset; text escapes control/Unicode and labels annotation UNTRUSTED DESCRIPTION. Client change to R or wrong digest in decide → BINDING_MISMATCH, pending unchanged, no decision. Correct designated reviewer digest creates exact immutable D; another reviewer/agent cannot decide (a variant config seeds rev_b with reviewer role to distinguish CALLER_MISMATCH from unknown actor). In fresh pending state reject at1500 creates rejected with immutable decision expiry=null, OK/exit0; execute returns REVIEW_REJECTED with A/rev1 and zero executions. Empty reason or wrong review digest cannot create a decision. Review state may reconcile but never rewrites stored P/R from submitted display content. Oracle: authored JSON-pointer inventory of every field, independently authored display golden, raw stored bytes and exact role/error checks; no rendering oracle from production template. Planned module: tests.acceptance.test_d11.

AC-11 additionally uses those [decision-reason Unicode boundaries](06-test-plan.md#decision-reason-unicode-boundaries) in fresh pending fixtures. Valid reasons persist verbatim in immutable D; invalid reasons create no decision and leave all DB rows/floor unchanged. Exact retries preserve decision bytes; a normalization-equivalent but scalar-distinct reason under the same approval_id returns IDEMPOTENCY_CONFLICT. Reason text cannot bypass reviewer, review-digest, lifecycle or execution checks.

## AC-12 / D12 — fail-closed storage/input

Initial: absent path, wrong-version/corrupt/copied DB, or seeded F depending variant. Missing DB not auto-created except init; missing parent/permissions INPUT_IO or STORAGE_ERROR by operation; existing init STATE_EXISTS and never overwrites. Unsupported app/version DATABASE_VERSION; invalid required loaded data STATE_CORRUPT. Hold writer lock using independent connection beyond2000ms: STORAGE_BUSY/no effect, bounded completion. Malformed input rejects before opening DB. Actor/ownership errors reveal no other-owner data. Exercise row/time/revision/report bounds and unexpected exception translation. Valid domain denial may advance floor/reconcile; storage/internal failure before commit must roll back. Inject SQLite write error before commit → STORAGE_ERROR/no effect; simulated COMMIT outcome-unknown reporting must demand identity reconciliation and never manufacture success. Oracle: DB file-existence/hash where meaningful, raw all-table snapshots, child exit/code, no traceback; test harness controls errors, not a permissive fallback. Planned module: tests.acceptance.test_d12.

## AC-16 — Runtime Boundary Audit

Command: `.venv/bin/python -B -m unittest tests.process.test_runtime_boundary -v`.
Initial: empty working dir, imported installed package and module/console entrypoints under supported CPython/site settings. Pure import has no application-controlled IO; help/version/invalid input/preclosed stdout have no DB/input access. Check attempted IO with a calibrated audit/instrumentation harness plus before/after filesystem snapshots; record blind spots. Runtime startup .pyc/site effects are explicitly excluded unless -B/-I controls them. Test real Python sys.stdout/sys.stderr=None behavior. No blanket "all OS writes prevented" assertion. Evidence includes exact interpreter/launch/env and allowed interpreter artifacts; all normal DB commands intentionally mutate only approved paths.

## AC-17 — Isolated distribution

Command: `.venv/bin/python -B -m unittest tests.distribution.test_installed -v`.
Build wheel/sdist from clean source with pinned tools; inspect archives, metadata, license, included docs/scenarios/goldens. Install wheel and sdist-built wheel into separate fresh virtualenvs outside source with network disabled for runtime/install after wheelhouse preparation. Run installed --help/--version, D01–D14/all, JSON/text, representative fault processes. Assert no source-path fallback. Run factory archive link lint for both artifacts; inspect README METADATA links and packaged docs under their actual roots. Independent oracle: archive member inventory, clean imports/entrypoint path, emitted golden bytes and link existence; absent future remote links cannot be called published. No package publication required.

## AC-18 — Deterministic interface and report compatibility

Command: `.venv/bin/python -B -m unittest tests.interface.test_reports -v`.
Run every built-in scenario twice in separate dirs/processes with same inputs/time/order, JSON and text. Require identical bytes, numeric D01..D14 order, no machine-dependent fields, exact schema/keys, stable error precedence, LF/escaping and size bounds. Compare authored D01/D08 JSON and D11 text/canonical goldens; no production-regenerated oracle. Different explicit schedules may have different reports; same schedule must match. Unsupported versions reject rather than silently coerce. API and CLI snapshots must match modulo process delivery. Oracle: frozen literals, independent JSON decoder/shape assertions, byte diff and report size counts.

AC-18 also checks the [decision-reason Unicode boundaries](06-test-plan.md#decision-reason-unicode-boundaries) through API/CLI JSON and text: canonical reason escapes agree with independent literals, valid escaped pairs render supplementary scalars, control characters are escaped, and normalization-equivalent strings retain distinct bytes. No existing golden is regenerated.

## Coverage and gate separation

D01→AC-01 through D14→AC-14. Runtime/process/distribution/determinism are AC-15–18. Local readiness requires all18 PASS with evidence on the candidate. Independent adversarial audit is a separate gate, not AC self-certification. Hosted CI is separate release evidence for the exact final SHA; it is NOT_RUN/PENDING_HOSTED_CI here. Source or contract changes invalidate affected results.
