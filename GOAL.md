# Approval Continuity Lab v0.1.0

Only in a subsequently authorized phase, build an offline modular monolith that answers: **under which explicit, observable conditions may this exact human approval still authorize this exact effect?**

Deliver a reference mediator, one simulated deploy_artifact operation, durable local SQLite store, adversarial scenario runner, deterministic JSON and readable terminal explanations. A reference effect commits only while all bound identities, executable fields, trusted revisions, eligibility and expiry checks hold. Consumption, target update and stored result share one atomic transaction. Identical retry retrieves that result without a second effect.

Acceptance is [AC-01–AC-18](docs/04-acceptance.md): D01–D14 plus CLI process, runtime, distribution and deterministic-interface gates. All local ACs need independent real evidence before LOCAL_READY; all are NOT_RUN now.

Naive and outside-boundary experiments must be labeled and isolated. No gateway, inbox, policy engine, production framework, provider credentials, real deployment, cloud, models, frontend, custom cryptography or framework integrations.

Guarantee: process-crash-consistent SQLite effects on a trusted local host under supported filesystem assumptions. No globally trusted clock, production authentication, sandbox, arbitrary downstream-effect inference, power-loss certification or external exactly-once promise.

Stop for irreconcilable contracts, unavailable required runtime/capabilities, unsupported filesystem locking, or tests requiring weaker guarantees. Otherwise complete only the authorized phase: spec → SPEC_READY; preflight → M0_PASS; build → LOCAL_READY with hosted CI pending. Independent audit and separately authorized publication must verify the final commit before RELEASE_READY. No automatic phase advance.
